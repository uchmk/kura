# kura — 確認事項（`question` の issue）の書き方と多数決

CLAUDE.md から分けた（2026-10-07）。質問を立てる・回答を反映する・票を入れるときに読む。

v0.102.0 から、確認事項は GitHub の issue（ラベル `question`）にした。**QUESTIONS.md は archive**（Q1-Q98。番号はそのまま参照できる）で、
新しい質問は書かない・読まない。昔の番号を調べるときだけ `grep -n '^## Q57' QUESTIONS.md` で 1 件を読む。

人の判断が要るときは、作業を止めて質問の issue を立てる。自動実行モードでも、対話中でも同じ。TODO.md には、どのタスクがどの質問で止まっているかだけを書く。

- **質問の立て方**: フォーム `.github/ISSUE_TEMPLATE/question.yml` の欄（背景・止めている TODO・選択肢・決め方）を本文に書く。
  - MCP なら `issue_write`（`labels: ["question", "lane:cloud"]`）、gh なら `gh issue create -l question,lane:cloud --body-file …`。
    QA のセッションは `lane:qa`、Windows のレーンは `lane:win`。
  - 選択肢には必ず推奨を 1 つ付ける（多数決に出すものは除く。下）。
  - 回答が来なくても推奨で進めてよい軽い事項なら、そう書き添える。
- **TODO.md への印**: 該当タスクの末尾に `（要確認: #N）` と付ける（昔の `（要確認: Q7）` も同じ意味）。
- **回答の反映**
  1. 持ち主は、issue に `回答: …` で始まるコメントを書く。merge-lanes のワークフローが毎時それを見て、ラベル `answered` を付ける。
  2. `answered` と `vote-decided` の issue は回答済みとして扱い、その内容でタスクを進める。
  3. 進めたら、TODO.md の `（要確認: #N）` を外し、版を書いたコメントを付けて issue を閉じる（理由は completed）。
  4. 回答があいまいなら、issue にコメントで聞き直す（`answered` を外す）。

### 多数決で進める質問（2026-10-02、持ち主の指示）

持ち主の回答を待たずに、**クラウド（質問を書いた側）と Windows x64 の 2 票が揃えば**決めてよい質問がある
（v0.101.2 までは ARM64 を入れた 3 票の多数決。ARM64 がリリースのときだけ動くようになり、2 票になった）。
持ち主の `回答:` は、いつでもそちらが優先する（多数決で入ったものを取り消すことも含む）。

- **対象は、技術的に正解を論じられる質問と、既定のキー割り当て・既定の動き**（後者は 2026-10-04、持ち主の指示）。次は対象にせず、これまでどおり持ち主を待つ:
  見た目、外に影響するもの（依存クレートの追加、リリース、workflow、セキュリティ）、
  持ち主の機械に関わるもの（ソフトを入れるかなど）。迷ったら対象にしない。
- **出し方**: ラベル `vote` を付け、選択肢に「（推奨）」を付けない（推奨に票が引きずられる）。
  書いた側が自分の票をコメントで入れる: `vote[cloud]: 2 — 理由`（1 行、この形のまま）。
- **票の入れ方**: Windows x64 のレーンは、毎回の実行で `vote` の issue に `vote[win]: 1 — 理由` のコメントを入れる
  （`windows-role.md` の「Votes」）。gh が使えなかった回は報告の `### Votes` に `- #57: 1 — 理由` と書き、
  merge-lanes が PR のマージ時に issue へコメントとして写す。**実機で見たことに根拠の無い票は数えない**（同じ系統のモデルが
  同じ前提から票をそろえても、独立した票にはならない。実機の票の値打ちは、実機で見たことにある）。
  数えない票には、マージする側が `uncount[win]: 理由` とコメントする。
  - 票を入れ直すときは新しいコメントを書く（同じ投票者の最新の 1 票だけを数える）。取り消すだけなら `uncount[<投票者>]:`。
- **数え方**（merge-lanes のワークフローが毎時。`scripts/merge-lanes.py` の `count_votes`）:
  - 2 票が同じ選択肢に揃ったら、ラベルを `vote-decided` にし、決まった選択肢をコメントで 1 回知らせる
    （2026-10-03、持ち主の指示で、その場で決める）。あとから持ち主が回答すれば、そちらが優先する。
  - 2 票が割れたら、または `owner`（持ち主が決めるべき）の票があれば、ラベルを `needs-owner` にし、持ち主を待つ。
    `needs-owner` は、持ち主が回答するか、`vote` を付け直すまで外れない。
  - 数えるのは、持ち主のアカウント（`OWNER` / `MEMBER` / `COLLABORATOR`）のコメントと、merge-lanes が写したコメントだけ。
- **進める**: `vote-decided` は回答済みと同じに扱う（自動実行モードの「回答済みの質問を優先」も含む）。
  CHANGELOG にも「#57、多数決」のように書く。
